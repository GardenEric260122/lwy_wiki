## 0. 已知踩过的坑（避免重蹈）

这几点是实际运维中真实发生过的故障，改进时优先消化：

| 现象 | 根因 | 已有对策 / 待办 |
|------|------|----------------|
| 回复「脑子一时转不过来」 | `.env` 里 `LIWENYA_BASE_URL` 漏了 `/v1`、或模型名中转不支持 | 见「§1 配置健壮性」——加启动自检 |
| 机器人自报「我是 Claude / Kiro」 | persona 开场触发模型安全护栏，拒演并暴露真身 | 已改为「虚构戏仿框架」开场；见「§4 人格稳定性」 |
| 掉线后日志每 5 分钟刷屏 `Timeout: ...sendMsg` | QQ 账号被踢下线，`fandom_notify` 仍尝试推送 | **待办**，见「§2 离线感知」 |
| VPS 上 `git pull` 了但不生效 | 运行目录 `~/liwenya_bot` 与仓库 `~/lwy_wiki` 是两份独立副本 | 见「§7 部署流程固化」 |

## 1. 配置健壮性（优先级：⭐⭐⭐）

**问题**：`.env` 填错（漏 `/v1`、模型名不存在、密钥失效）时，现在要到用户发消息、看日志才发现，且报错信息不直观。

**改进**：在 `bot.py` 启动时做一次**配置自检**，把问题在启动阶段就暴露出来。

- 检查 `LIWENYA_API_KEY` 非空；
- 检查 `LIWENYA_BASE_URL` 以 `/v1` 结尾（不是就 warning）；
- 可选：启动时调一次 `client.models.list()`，确认 `LIWENYA_MODEL` 在返回列表里，否则打印可用模型名。

**改哪**：`bot.py` 里 `nonebot.init()` 之后、`nonebot.run()` 之前加一个 `_preflight_check()`。
**验证**：故意把模型名改错，启动应立刻在日志里报「模型 xxx 不可用，可用：...」而不是等发消息才失败。

## 2. 离线感知与静默（优先级：⭐⭐⭐）

**问题**：QQ 账号掉线后，`fandom_notify` 的定时任务照常轮询、照常尝试 `send_group_msg`，每轮都抛 `Timeout` 塞满日志（真实发生过）。

**改进**：推送前先判断 bot 是否在线、拿不到 bot 就跳过本轮。

`fandom_notify.py` 里把：
```python
bot = get_bot()          # 拿不到会抛异常
```
改成先探测：
```python
from nonebot import get_bots
if not get_bots():        # 没有已连接的 bot，说明掉线
    logger.debug("[fandom_notify] 无在线 bot，跳过本轮推送")
    return
```
并且**掉线期间不要滑动 `_last_ts`**，否则恢复后会漏推这段时间的变更。当前代码是「不管推没推成功都滑动时间戳」，应改为**推送成功后才滑动**。

**验证**：手动停掉 NapCat 模拟掉线，日志应只有 debug 级「跳过本轮」，不再刷 `Timeout` 报错。

## 3. 成本与限流（优先级：⭐⭐）

现在的控成本手段（仅 @ 触发、冷却、限轮数）是够用的底线，可再加：

- **每日 token 预算**：在 `liwenya_chat.py` 里累计当日 `usage.total_tokens`，超阈值后当天只回固定一句「今天说太多了，明天再问」。防止被人刷爆账单。
- **单用户频率限制**：现在冷却是「按会话（群/私聊）」，群里多人时一个冷却挡所有人。可细化为「按 user_id」维度，或群内加更长冷却。
- **上下文按 token 而非轮数裁剪**：`MAX_TURNS` 是按条数截断，长消息仍可能超长。可改为累计字符/token 估算后裁剪。

**改哪**：`liwenya_chat.py` 的 `_call_llm` 与会话状态部分。

## 4. 人格稳定性（优先级：⭐⭐）

persona 开场已改为「虚构戏仿游戏」框架，模型不再拒演。后续可继续巩固：

- **few-shot 锚点**：在 system prompt 后追加 2~3 组「问→李文亚式答」示例（可从 `.claude/skills/liwenya-perspective/references/` 里挑），让语气更稳。
- **回复长度硬约束**：persona 已要求「群聊 1-3 句」，但模型偶尔超。可在代码侧对超长回复做截断兜底。
- **换模型时重测护栏**：不同 Claude 版本（sonnet / opus / haiku）安全护栏松紧不同，换 `LIWENYA_MODEL` 后务必用「你是谁 / 你是不是 AI」重新验证是否稳定入戏（见 §1 自检可顺带做）。

## 5. 功能扩展（优先级：⭐，对应实施方案阶段 4–5）

按需从 `plugins/` 加插件，NoneBot2 生态多数有现成轮子：

- **GitHub 提醒**：轮询本仓库 commits / issues / releases，或配 Webhook 更实时。可复用 `fandom_notify.py` 的定时任务骨架。
- **B站动态 / 开播提醒**：社区有 `nonebot-plugin-bilibili` 类插件。⚠️ B站 API 易变、部分需登录态，是最不稳的一环，做好维护预期。
- **群管**：入群欢迎、关键词过滤、禁言、签到——多有现成插件，可套李文亚口吻。
- **消息去重 / 合并推送**：Fandom 短时间多次变更时合并成一条，减少刷屏（现在是最多 5 条 + 省略提示，可再优化）。

## 6. 可观测性与测试（优先级：⭐）

- **健康日志**：定期（如每小时）打一条「bot 在线、今日已回复 N 条、消耗 M token」的心跳日志，便于回看运行状况。
- **本地冒烟测试**：`test_once.py` 已可验证 API + persona。建议把「你是谁 / 你是不是 AI」这几个护栏测试固化成一个脚本，换模型或改 persona 后一键跑。
- **NapCat 掉线告警**：监听 `notice.bot_offline` 事件（日志里出现过），触发时通过其他渠道（如给 SUPERUSER 发一条、或写入监控）提醒你去重新扫码，而不是等群友反馈才发现。

## 7. 部署流程固化（优先级：⭐⭐⭐，避免「改了不生效」）

**关键**：VPS 上有**两份** `liwenya_bot`，位置独立：

- `~/lwy_wiki/liwenya_bot/` —— git 仓库副本，`git pull` 更新的是这份；
- `~/liwenya_bot/` —— 机器人**实际运行**读取的那份（NoneBot2 从 `~/liwenya_bot/qqbot/` 启动）。

只 `git pull` **不会**让运行中的 bot 生效。正确的更新流程（三步）：

```bash
# 1) 更新仓库副本
cd ~/lwy_wiki && git pull

# 2) 把改动的文件同步到运行目录（persona / 插件 / bot.py 等）
cp ~/lwy_wiki/liwenya_bot/liwenya_persona.txt ~/liwenya_bot/liwenya_persona.txt
# 若改了插件：cp ~/lwy_wiki/liwenya_bot/qqbot/plugins/*.py ~/liwenya_bot/qqbot/plugins/

# 3) 重启生效
sudo systemctl restart liwenya-bot
sudo journalctl -u liwenya-bot -f    # 看日志确认 OneBot 连入、无报错
```

> `.env`（含密钥）不入库，运行目录 `~/liwenya_bot/qqbot/.env` 那份需单独手改，
> `git pull` 带不过来。改完记得 `grep -E "BASE_URL|MODEL" ~/liwenya_bot/qqbot/.env` 核对。

**根治建议**：让两份合一——把 systemd 的 `WorkingDirectory` 直接指向 `~/lwy_wiki/liwenya_bot/qqbot`，
运行目录即仓库目录，以后只需 `git pull + restart`，不用再复制。这是消除本类故障的最优解。
